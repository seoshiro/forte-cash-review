# Torch: применимость advisories и подготовленное обновление

Текущий исследовательский runtime: torch 2.8.0+cu128, torchvision 0.23.0+cu128. После установки выполнен повторный pip-audit по всем пакетам; CUDA local version labels сопоставлены с upstream base versions только для поиска записей PyPI. Найдены восемь advisories в torch, пропусков пакетов нет. Нулевой предыдущий отчёт относился к CPU-окружению и не является результатом этого аудита.

Источники вычисления: .private/dependency-audit-cuda.json, .private/cuda-pypi-audit.json, .private/security-safe-summary.json. Не использовать --ignore-vuln для получения формального нуля.

После добавления LM Format Enforcer и interegular выполнен новый read-only lookup всех 70 фактически установленных пакетов через PyPI: affected packages 1, unique advisory IDs 8, skipped 0. Этот новый запуск выполняет scripts/audit_installed.py, а не отсутствующий в product venv pip-audit CLI. Источники: .private/dependency-audit-structured.json и .private/structured-security-safe-summary.json. Старый scanner report сохранён отдельно.

По PT2 проверен upstream PR 176791: закрыт, `merged=false`, `merged_at=null`; заголовок и предложение касаются передачи weights_only в torch.export.load. merge_commit_sha в REST metadata сам по себе не доказывает merge. Нельзя утверждать, что именно этот PR вошёл в релиз. Запись PyPA ограничивает affected range версией 2.10.0; отсутствие записи у новой версии не равно независимому доказательству устранения всех небезопасных десериализаций. Не принимать PT2 и другие исполняемые model artifacts даже после обновления.

Дополнительно получены официальные исходники tag v2.14.1, с SHA256 каждого файла в .private/pt2-release-review/safe-summary.json. В torch/_export/serde/serialize.py, строки 438–441, после torch.load(weights_only=True) остаётся общий except Exception и fallback torch.load(weights_only=False). Это прямое основание не считать новую версию доказанным исправлением PT2. [Версионированный источник](https://github.com/pytorch/pytorch/blob/v2.14.1/torch/_export/serde/serialize.py). Изменение версии может закрыть остальные явно версионированные advisories, но не заменяет ограничение входных путей.

Для отдельного BUDGET-01 подготовлен process-local запрет torch.load, torch.serialization.load, torch.jit.load и torch.export.load. Он не меняет установленную библиотеку или ОС, должен применяться до fixed safetensors model load и проходить реальную проверку загрузки модели. Такая мера блокирует перечисленные Python entry points, а не все возможные алиасы/нативные пути пакета. Она пока не включена в работающий frozen baseline. Операции RNN/LSTM/LU/JIT scripting не становятся допустимыми пользовательскими входами; сервис получает только bounded MOV→RGB, не tensor programs или checkpoints. Публичный доступ остаётся заблокированным до отдельной проверки runtime, входных границ, guard и всего API.

## Подготовленный совместимый кандидат

Официальные Windows x64 CPython 3.12 wheels доступны для torch 2.14.1+cu130 и torchvision 0.29.1+cu130; torchvision metadata требует torch>=2.14.0. CUDA 12.8 wheel этой новой ветки в проверенном индексе нет. Официальные URL, размеры и SHA256 закреплены в config/runtime-upgrade.json. Драйверный API локально вернул 13030, что проходит preflight для CUDA 13.0. Это проверка ABI/metadata/driver API, а не успешный neural benchmark новой сборки. В PyPI metadata кандидата перечисленных advisories нет; PT2 оговорка выше сохраняется.

Новый Torch runtime не установлен. Текущая .venv и работающий pipeline не изменяются. scripts/stage_patched_runtime.py без аргументов только показывает план. Режим --prepare отказывается работать при активной подготовке/benchmark/tuning, проверяет два wheel в .private/runtime-upgrade и устанавливает их с общими зависимостями в отдельную .venv-patched. Дополнительные зависимости resolver могут увеличить объём; размеры в конфигурации относятся только к двум указанным wheel. Веса Qwen повторно не скачиваются. Глобальные Python, драйверы, защита ОС и network grants не меняются.

Начата отдельная download-only подготовка официальных SHA-pinned CUDA wheels: scripts/prepare_runtime_artifacts.py. Она не устанавливает пакеты и не запускает GPU. Малые wheels bitsandbytes 0.50.2 (MIT) и accelerate 1.15.0 (Apache-2.0) уже проверены по SHA и сохранённым license files отдельно в .private/quantization-preflight; bitsandbytes wheel содержит cuda128 и cuda130 DLL. [Официальная Windows таблица](https://huggingface.co/docs/bitsandbytes/main/en/installation) указывает поддержку sm89 для CUDA 12.8 и 13.0. Это metadata/native-file preflight, не доказательство совместимости с Transformers 5 или работоспособности NF4 на этой машине. Никакая quantization dependency в текущую .venv не устанавливалась. Текущий статус CUDA artifacts берётся из progress/preflight файлов.

После завершения текущей оценки: сохранить её lock/JSON/commit, подготовить .venv-patched, получить новый фактический lock и полный advisory audit без исключений; выполнить синтетические тесты, BF16/processor check, реальный TRAIN benchmark с памятью и latency и тот же train/tune протокол. Сохранять baseline и новую оценку раздельно; не приписывать разницу версии runtime преимуществу temporal refinement. Затем выполнить локальный model API QA с проверкой JPEG/PTS и переименования. Не переключать запуск сервиса на новый interpreter, пока эти проверки не пройдут. Старую .venv оставить для отката.

Публичный relay и постоянный API-ключ всё ещё ждут прямого согласия пользователя. Этот документ не является подтверждением готовности внешнего сервиса или безопасности всего нативного стека.
