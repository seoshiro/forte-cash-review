# Testable alternatives if primitive facts fail

No alternative below is adopted or claimed to fit the machine from a model name. The [class audit and one bounded CPU control](cpu-facts-preflight.md) are complete: RT-DETR was rejected as a semantic replacement before weights; CPU primitive accuracy did not improve and its text gate failed. That stage downloaded no new weights. A later [different-VLM stage](internvl-visual-control.md) pinned and measured InternVL on actual synthetic images; its visual gate also failed, so no TRAIN pilot followed. Preserve XCLIP and every closed candidate/held-out boundary.

## Bounded backend comparison without a new download

The already pinned Qwen GGUF weights declare [Apache2](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct-GGUF/blob/1cd86afb9a95c410a6038ab3b40d8b578c892266/README.md); [llama.cpp code is MIT](https://github.com/ggml-org/llama.cpp/blob/b11712/LICENSE). The separately registered CPU comparison retained the six fact/binding request bodies, scoring, weights, template and sampling. It changed requested device/offload settings and separately increased the text timeout; session, workload and interleaving also differed, so backend cause was not isolated. The pinned [argument parser](https://github.com/ggml-org/llama.cpp/blob/b11712/common/arg.cpp#L2505-L2514) supports `--mmproj-device none`; [device none](https://github.com/ggml-org/llama.cpp/blob/b11712/common/arg.cpp#L2634-L2641) disables offload. These flags and zero GPU layers were requested with the same artifact identities and temporary local key.

This tests backend sensitivity, not the exact GPU kernel or model capacity. The separately registered CPU facts/binding control has now run once and failed its text prerequisite (2/3 exact facts,8/9 fields,3/3 GT binding). Its actual costs and sampled RAM pressure are documented in `cpu-facts-preflight.md`. Direct coordinate-to-label tasks were not repeated; conditional images did not run. The CPU candidate is closed without a bank transition or another prompt search.

## Independent physical-state classifier

Prefer a narrow detector/tracker/state-machine route over another unbounded VLM prompt search. Candidate: [PekingU RT-DETRv2 R18 weights](https://huggingface.co/PekingU/rtdetr_v2_r18vd), whose model repository declares Apache2; the [upstream code license](https://github.com/lyuwenyu/RT-DETR/blob/main/LICENSE) is also Apache2. The locally installed Transformers RTDetrV2 model/processor classes import successfully, without loading weights or using the GPU. Built-in import is not forward-pass or memory evidence.

The initial proposed capability was anonymous whole-body person presence and crossing of a locally reviewed zone. The actual pinned COCO class map has80 classes including person, but no cash/cashier/procedure classes. Official binary/point labels provide no independent truth for person/zone/role/action conditions, and no justified mapping was established. Therefore this route was rejected before weights/state-machine implementation. A bbox is not proof of an action, and person presence does not establish unfinished service, cash counts or legal applicability.

Any future adoption would first require independently justified primitive truth and applicability, then pinned code/weights/licenses and a bounded resource/quality preflight. No future run is registered or implied here. Allocation success alone would not authorize a bank transition. No RT-DETR speed, six-GB fit or event accuracy was measured.

The small SmolVLM candidate was considered only through public metadata; it was not selected or downloaded. Its model card's stated use limitations must be resolved before any task adoption. This is another reason to prioritize an explicit physical-state path with a narrow, testable claim.
