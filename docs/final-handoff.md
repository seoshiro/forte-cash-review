**Единственная актуальная точка входа UI и API:** https://sword-fire-sim-conversion.trycloudflare.com

Ключ жюри и доступ истекают **18 октября 2026, 18:59:59 UTC / 23:59:59 Астаны (UTC+5)**. Это установленный срок нашей сессии; фактическое время окончания оценки организаторами не подтверждено. Компьютер Windows и интернет должны оставаться включёнными. За uptime не платили. Quick Tunnel имеет временный hostname и не гарантирует доступность; перезапуск самого туннеля меняет адрес. [Официальные ограничения](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Frontend, загрузка, фоновые задания и API работают с реальным локальным baseline. **Качество слабое:** ранее зафиксированная единственная оценка TUNE — **TP 1, FN 4, FP 3, TN 1; F1 = 2/(2+3+4) = 0.222222…**. Это исходные 9 записей / 8 уникальных содержимых, не независимая итоговая проверка и не балл жюри. Повторного доступа к TUNE/HOLDOUT на этом этапе не было. [Сохранённая оценка](xclip-tune.md).

**Типизация, наблюдаемое действие и применимость норм не подтверждены.** Сервис отдаёт один бинарный кандидат с `type: unclassified_suspected_event` и явным предупреждением, что тип и правило не установлены. Нормативную ссылку он не придумывает. Обязательная JSON-форма реализована, смысловые требования ТЗ выполнены частично. Полное обнаружение нескольких событий, релевантность доказательств и качество другого ракурса не приняты. Адаптер отклонён, исходный baseline сохранён; новые модели не ищутся. Прохождение software-тестов не означает accuracy модели.

## Ключ и запросы

На выбранном Windows из корня проекта открыть `.private/final-access/Open-Jury-Access.cmd`. Локальное окно показывает текущий URL, отдельный **временный ключ жюри** и expiry. Ключ не выводился в чат, Git, JavaScript, URL, скриншоты или логи. Вне окна он хранится в user-scoped DPAPI. Окно не открывать через облачный capture. Пользователь сам передаёт URL и ключ жюри по разрешённому каналу; от его имени ничего не отправлено.

Оба метода требуют `X-API-Key`:

```powershell
# Значение ключа пользователь задаёт локально; здесь секрета нет.
$taskEndpoint='https://sword-fire-sim-conversion.trycloudflare.com'
curl.exe -X POST "$taskEndpoint/api/v1/analyze" -H "X-API-Key: $env:TERENOI_JURY_KEY" -F 'file=@C:\path\input.mov'
curl.exe "$taskEndpoint/api/v1/jobs/JOB_ID_FROM_POST" -H "X-API-Key: $env:TERENOI_JURY_KEY"
```

POST принимает multipart-поле `file`, MOV и возвращает `job_id`. GET возвращает `processing`, `done` либо `failed`. У `done` только обязательные поля; `verdict` — `violation` или `no_violation`, отрицательный список пуст. Техническая ошибка не превращается в отрицательный вердикт. При занятой мощности новая загрузка отклоняется `429` с `Retry-After`; очередь не прячет превышение времени. Бюджет native-job — 295 секунд от приёма, включая upload, при конкурсном пределе 300 секунд. Результаты привязаны к owner-key, приватные/raw пути закрыты; фоновый TTL — один час.

## Отзыв и перезапуск

- `.private/final-access/Revoke-Jury-Key.cmd` немедленно отзывает ключ жюри на следующем API-запросе; остальные owner-keys не открывают задания жюри. Отзыв не отменяется незаметно при рестарте.
- `.private/final-access/Restart-Origin.cmd` перезапускает только наш origin с тем же ключом, хранилищем и публичным URL. Завершённые задания сохраняются; прерванное нужно загрузить заново после `failed`.
- `.private/final-access/Stop-All-Access.cmd` останавливает только принадлежащие этому профилю origin и connector.
- При штатном завершении всей сессии, включая expiry, после остановки owned-процессов удаляются её временные uploads/results из `.private/final-service/jobs`. Рекурсивное удаление разрешено только для проверенных opaque job-папок внутри точного project-root, при правильном contract marker и свободном native-store lock. Исходные видео, разметка и другие проекты не затрагиваются. Перезапуск одного origin эту очистку не вызывает. После аварийного выключения fallback — `.private/final-access/Cleanup-Stopped-Uploads.cmd`; при работающем native API он откажется удалять данные.
- После остановки всей сессии, до её expiry: из корня выполнить `.venv-patched\Scripts\python.exe scripts/final_access.py start`, затем `... scripts/final_access.py status`. Дождаться `READY`, проверить новый URL и передать его заново. Перезапуск самого туннеля меняет hostname; старый адрес нельзя считать рабочим. Команда `start` использует прежний DPAPI-ключ, не продлевает срок и не создаёт новые credentials.

Текущее состояние и URL: `.private/final-access/endpoint.json` и `.../safe-summary.json`. После expiry доступ закрывается и процессы завершаются. Продление автоматически не выполняется. Защита ОС, firewall, DNS, WARP, router, power policy, autostart и службы не менялись.

Предыдущие research/partial публичные профили отозваны; их owned origin/connector остановлены. Использовать только актуальный адрес в начале этого документа и в локальном окне ключа. Финальный connector перепроверяется после каждого полного перезапуска; исходный baseline и обязательный transport не меняются.

## Исходники и сдача

[Репозиторий](https://github.com/seoshiro/forte-cash-review) остаётся **PRIVATE**. Ссылка и API-ключ не дают жюри доступ к GitHub. Владельцу нужно отдельно выдать доступ конкретной учётной записи жюри либо передать проверенный code-only ZIP по разрешённому каналу. Учётная запись получателя не предоставлена, приглашения не отправлялись, visibility не менялась. Code-only архив готовится из прошедшего source/history-аудит commit и указан в локальном HANDOFF.

Код — Apache-2.0; код/веса XCLIP и зависимости с provenance перечислены в [лицензиях](licenses.md). В Git/ZIP нет видео, кадров, разметки, приватных результатов, ключей, runtimes и весов. Чистый клон также не содержит приватный TRAIN prototype-pack; локальный запуск на выбранной машине использует подготовленные ранее артефакты. Передача приватного пакета в другой контур требует разрешённого канала и отдельного соблюдения ограничений данных.

Для пользователя подготовлены URL UI/API, локальное получение/отзыв ключа, запросы, запуск, архитектура, лицензии, нормативные источники и честные ограничения. Канал сдачи и подтверждение приёма отсутствуют; форму не отправляли и организаторам не писали. Главные блокеры полной конкурсной готовности — слабая детекция и отсутствующая подтверждённая типизация/применимость правил.
