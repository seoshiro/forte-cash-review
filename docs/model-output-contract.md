# Локальный формат и память

Первый BF16 benchmark: 0/3 валидных TRAIN observations; синтетика и отдельная 12-frame проба тоже не прошли структуру. После компактного prompt и бюджета 512 токенов: 1/3, ещё два ответа отклонены как time_outside_window; синтетика и отдельная 12-frame проба валидны. Источники неизменяемых запусков: .private/benchmark-bf16-initial и .private/benchmark-compact-json-2. Это технические ошибки формата, не F1 обнаружения. Средние 30.40 и 37.36 секунды относятся к одной шестикадровой observation с decode, не к полному видео/API.

Текущий эксперимент constrained-frame-id-3 использует локальный LM Format Enforcer 0.11.3 (MIT). Схема ограничивает JSON, whitelist rule_id, идентификаторы только переданных кадров, число событий и длины строк. Код отображает выбранный frame_id на исходный PTS; не исправляет произвольную временную отметку. Обычный строгий validator сохраняет проверки диапазонов и ошибок. Незавершённый JSON — технический сбой, не no_violation.

В опубликованном wheel интеграция Transformers импортирует удалённый PreTrainedTokenizerBase из transformers.tokenization_utils. Вместо изменения site-packages используется небольшой адаптер документированного tokenizer-data API с сохранённой MIT attribution. Установленный Transformers 5.20.1 поддерживает prefix_allowed_tokens_fn; [upstream integration](https://github.com/noamgat/lm-format-enforcer/blob/main/lmformatenforcer/integrations/transformers.py) показывает тот же механизм. [Документация LMFE](https://github.com/noamgat/lm-format-enforcer) прямо отделяет соблюдение формата от смысловой корректности.

Локальный chat_template.json этой Instruct-версии не содержит enable_thinking или think tag. Никакая придуманная команда отключения thinking не применяется. Синтетический тест с шестью сгенерированными изображениями завершился валидной схемой: 366/512 output tokens, 58.25 s. Это проверка формата на искусственном входе, не качества распознавания. .private/synthetic-structure-diagnostic-safe-summary.json хранит только агрегаты. TRAIN/TUNE ещё измеряются; holdout закрыт.

max_memory_allocated считает память живых tensor allocations, max_memory_reserved — память caching allocator. Это два отдельных пика, не обязательно одновременно; разность пиков нельзя трактовать как текущий свободный cache. Определения проверены по docstrings установленного torch.cuda.memory. Физическая память адаптера по nvidia-smi — 6141 MiB. Пик allocator reserved 6852 MiB не означает наличие такого физического VRAM. [WDDM использует виртуальное адресное пространство GPU](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/gpu-virtual-memory-in-wddm-2-0); [Microsoft различает dedicated и shared memory](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/).

Во время синтетического процесса read-only PDH snapshot показал dedicated 5242.816 MiB, shared 78 MiB, committed 5320.816 MiB. Одновременный nvidia-smi adapter snapshot: used 5243 MiB, free 678 MiB, driver reserved 221 MiB. Эти значения не относятся к моменту прежнего пика 6852 MiB и не доказывают причину этого пика. Следующий bounded monitor сохраняет отдельные gauge maxima; они тоже не объявляются одновременными. [NVIDIA](https://docs.nvidia.com/deploy/nvidia-smi/index.html) предупреждает об ограничении per-process memory reporting в WDDM; PDH применяется отдельно от adapter snapshot.

Явный model CPU offload не настроен: загрузка BF16 с .to('cuda'), без device_map или Accelerate. Синтетический аудит параметров подтвердил 4255064064 bytes на cuda:0, CPU parameters не обнаружены. Это расположение tensor parameters, не доказательство физической residency каждой страницы WDDM. Общую Windows shared memory нельзя называть явным модельным offload.
