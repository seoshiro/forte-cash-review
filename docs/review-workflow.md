# Ручная проверка эпизода

Сервис обрабатывает загруженные MOV. Внутреннее уведомление появляется после завершения анализа и получения конечного состояния проверки контекста. Оно предлагает ручную проверку, не объявляет доказанное нарушение. Внешних push, email, Telegram, автоматических санкций и обучения на решениях нет.

Карточка сохраняет исходные наблюдение, кадры, таймкод и проверенное правило. BUDGET-01 использует один уже предусмотренный проход по кандидату; дополнительные нейросетевые проходы ради интерфейса не добавляются. Другие эпизоды получают явное ограничение контекста. Старые uniform результаты без явного повторного подтверждения показываются как ограниченные. Отсутствующий detail или pending контекст не дают уведомления и не позволяют сохранять решение.

«Подтвердить», «Отклонить» и «Недостаточно данных» — состояния человека. Они сохраняются в отдельном private reviews.json под блокировкой и привязаны к SHA256 исходного result.json. Сам result.json не изменяется. Собственные UI GET/PUT endpoints защищены тем же X-API-Key и изоляцией владельца; /api/v1 по-прежнему возвращает только два официальных verdict и прежнюю схему. Решения удаляются вместе с job согласно существующему TTL.

Синтетические тесты проверяют сохранение, повторное открытие, неизменность конкурсного ответа, разделение владельцев, отсутствие уведомлений при незавершённом/отсутствующем контексте. Headless Edge с отключённым GPU проверил три решения, повторное получение сохранённого решения, кадры JPEG, desktop/mobile и очистку старого результата при выборе нового видео. Скриншоты только искусственных материалов; качество детектора этими тестами не измеряется.
